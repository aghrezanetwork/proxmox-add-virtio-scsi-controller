🌐 English version: Add a VirtIO SCSI controller alongside VMware PVSCSI in Proxmox

افزودن کنترلر VirtIO SCSI در کنار VMware PVSCSI

این راهنما روش آزمایش‌شده در یک محیط Proxmox را توضیح می‌دهد: کنترلر VMware PVSCSI موجود و دیسک‌های متصل به آن حفظ می‌شوند و یک کنترلر VirtIO SCSI اضافی به QEMU معرفی می‌شود تا ویندوز بتواند آن را شناسایی کند.

نمونه محیط: Proxmox VE 9.2، ویندوز ۱۱، VMID برابر 105. در محیط خودتان VMID و وضعیت را حتماً بررسی کنید.

قبل از شروع: نکات مهم

  • این کار برای مدیر سرور و روی VM آزمایشی/دارای نسخه پشتیبان انجام شود.
  • روش زیر از آرگومان سفارشی QEMU استفاده می‌کند؛ کنترلر سفارشی ممکن است مانند سخت‌افزار تعریف‌شده از طریق رابط عادی Proxmox در همه عملیات مدیریتی، Migration یا عیب‌یابی پوشش یکسانی نداشته باشد.
  • از تنظیمات VM نسخه پشتیبان بگیرید. این نسخه پشتیبان فقط فایل پیکربندی را نگه می‌دارد، نه داده‌های داخل دیسک‌ها.
  • اگر VM از قبل مقدار args: در تنظیمات دارد، آن را کورکورانه جایگزین نکنید؛ ابتدا مقدار موجود را بررسی کنید. دستور نمونه ممکن است مقدار قبلی args را جایگزین کند.
  • در این سناریو کنترلر دوم بدون دیسک اضافه می‌شود. اضافه‌کردن دیسک به آن مرحله‌ای جداگانه است.
هشدار: پیش از اجرای دستور نهایی، VM را کاملاً خاموش کنید. اگر VM مهم یا عملیاتی است، ابتدا روش را روی یک VM تستی اجرا و Backup/Restore و Migration را طبق نیاز سازمان آزمایش کنید.

مرحله ۱ — بازکردن Shell در Proxmox

  1. وارد پنل وب Proxmox شوید؛ معمولاً نشانی به شکل https://IP-سرور:8006 است.
  2. از ستون سمت چپ، Node موردنظر را انتخاب کنید.
  3. گزینه Shell را باز کنید. دستورات این راهنما را در Shell میزبان Proxmox اجرا کنید، نه داخل ویندوز مهمان.

مرحله ۲ — پیدا کردن شناسه ماشین مجازی

qm list

کار دستور: فهرست ماشین‌های مجازی، شناسه (VMID)، نام و وضعیت آن‌ها را نمایش می‌دهد.

در این راهنما شناسه نمونه 105 است. اگر VM شما شناسه دیگری دارد، در دستورهای بعدی آن را جایگزین کنید.

مرحله ۳ — بررسی پیکربندی فعلی VM

qm config 105

کار دستور: تنظیمات VM شماره 105 را نشان می‌دهد. در نمونه این راهنما، موارد کلیدی چنین بودند:

تنظیممعنی
scsihw: pvscsiمدل کنترلر SCSI فعلی VMware PVSCSI است.
scsi0، scsi1، scsi2سه دیسک موجود که به کنترلر SCSI فعلی متصل‌اند.
ide2: local:iso/virtio-win-....isoISO درایورهای VirtIO به VM متصل است؛ مسیر/نام ISO در هر محیط ممکن است متفاوت باشد.
machine: pc-q35-...نوع ماشین مجازی Q35 است.

اگر کنترلر فعلی PVSCSI است، خط scsihw: pvscsi را تغییر ندهید؛ هدف، حفظ آن و اضافه‌کردن کنترلر دوم است.

مرحله ۴ — گرفتن نسخه پشتیبان از فایل تنظیمات

cp /etc/pve/qemu-server/105.conf /root/105.conf.backup

معنی اجزا:

  • cp: فایل را کپی می‌کند.
  • /etc/pve/qemu-server/105.conf: فایل پیکربندی اصلی VM شماره 105 است.
  • /root/105.conf.backup: مسیر ذخیره کپی پشتیبان است.

این دستور فقط از تنظیمات VM کپی می‌گیرد؛ از محتویات دیسک مجازی Backup تهیه نمی‌کند.

برای اطمینان از ساخته‌شدن فایل:

ls -l /root/105.conf.backup

دستور ls -l وجود فایل، اندازه و زمان تغییر آن را نمایش می‌دهد.

مرحله ۵ — (اختیاری) دیدن فرمان QEMU

qm showcmd 105 --pretty

کار دستور: فرمانی را نمایش می‌دهد که Proxmox برای اجرای VM به QEMU می‌سازد. گزینه --pretty خروجی را خواناتر می‌کند. این دستور به‌خودی‌خود VM را روشن یا پیکربندی را تغییر نمی‌دهد.

در خروجی نمونه، کنترلر موجود با خطی مشابه این ساخته شده بود:

-device 'pvscsi,id=scsihw0,bus=pci.0,addr=0x5'

و دیسک‌ها به گذرگاه همین کنترلر متصل بودند. این مرحله برای شناخت وضعیت فعلی مفید است، اما برای همه نصب‌ها الزام‌آور نیست.

مرحله ۶ — خاموش‌کردن VM

از رابط Proxmox، VM موردنظر را به‌صورت عادی خاموش کنید و مطمئن شوید وضعیت آن stopped است. از خاموش‌کردن اجباری VM مگر در شرایط ضروری خودداری کنید.

برای مشاهده وضعیت می‌توانید از این دستور استفاده کنید:

qm status 105

این دستور وضعیت VM را نشان می‌دهد؛ برای تغییر تنظیمات، VM باید خاموش باشد.

مرحله ۷ — افزودن کنترلر VirtIO SCSI دوم

در محیط نمونه، دستور زیر پذیرفته شد و Proxmox اعلام کرد تنظیمات VM به‌روزرسانی شده است:

qm set 105 --args '-device virtio-scsi-pci,id=virtioscsi1,bus=pci.0'

معنی هر بخش:

بخشکاربرد
qm set 105تغییر تنظیمات VM شماره 105.
--argsثبت آرگومان‌های اضافی برای QEMU.
-device virtio-scsi-pciدرخواست ایجاد کنترلر VirtIO SCSI مجازی.
id=virtioscsi1شناسه داخلی یکتا برای این دستگاه در QEMU.
bus=pci.0اتصال کنترلر به گذرگاه PCI ماشین مجازی.
نکته فنی مهم: این دستور آرگومان سفارشی QEMU را به پیکربندی اضافه می‌کند؛ آن را معادل قابلیت رسمی «افزودن کنترلر دوم» در رابط Proxmox در نظر نگیرید. در صورت وجود args قبلی، آن را حفظ و با آرگومان جدید ترکیب کنید؛ دستور بالا ممکن است مقدار قبلی را جایگزین کند. همچنین کنترلر سفارشی ممکن است نیازمند بررسی جداگانه برای Migration، Backup/Restore و سازگاری با نسخه‌های بعدی باشد.

مرحله ۸ — تأیید ذخیره‌شدن تنظیمات

qm config 105

در خروجی بررسی کنید خطی شبیه زیر وجود داشته باشد:

args: -device virtio-scsi-pci,id=virtioscsi1,bus=pci.0

این فقط تأیید می‌کند آرگومان در پیکربندی ثبت شده است؛ به‌تنهایی ثابت نمی‌کند کنترلر در زمان اجرای VM بدون خطا ساخته می‌شود.

مرحله ۹ — روشن‌کردن VM و بررسی ویندوز

  1. از رابط Proxmox ماشین مجازی را روشن کنید.
  2. اگر VM روشن نشد، تلاش‌های مکرر نکنید؛ پیام خطا را بررسی کنید و تنظیمات را قبل از تغییر بیشتر بازبینی کنید.
  3. داخل Windows 11، کلیدهای Win + X را بزنید و Device Manager را باز کنید.
  4. بخش‌های Storage controllers و Other devices را بررسی کنید. نام دستگاه ممکن است بسته به نسخه QEMU و درایور کمی متفاوت باشد.
  5. اگر کنترلر ظاهر شد اما درایور نداشت، از ISO درایورهای VirtIO متصل به VM استفاده کنید. درایور متناسب با Windows و معماری مهمان را انتخاب کنید؛ از انتخاب تصادفی فایل INF خودداری کنید.
  6. پس از نصب، در Device Manager وضعیت دستگاه را بررسی کنید و در صورت نیاز ویندوز را Restart کنید.

نصب درایور به‌تنهایی کنترلر مجازی را ایجاد نمی‌کند؛ QEMU باید دستگاه را به VM ارائه کند. از طرف دیگر، وجود آرگومان در پیکربندی به‌تنهایی تضمین نمی‌کند ویندوز دستگاه را بدون خطا شناسایی کند.

عیب‌یابی و بازگشت به وضعیت قبلی

اگر VM روشن نمی‌شود

  • متن کامل خطای Proxmox را ذخیره کنید.
  • بررسی کنید VM خاموش بوده و مقدار args با آرگومان‌های قبلی تداخل نداشته باشد.
  • بدون بررسی، فایل تنظیمات را با نسخه پشتیبان جایگزین نکنید؛ ابتدا تفاوت فایل فعلی و پشتیبان را بررسی کنید.

بررسی تفاوت پیکربندی با نسخه پشتیبان

diff -u /root/105.conf.backup /etc/pve/qemu-server/105.conf

این دستور فقط تفاوت دو فایل را نمایش می‌دهد و چیزی را تغییر نمی‌دهد.

اگر لازم شد تنظیم سفارشی را حذف کنید

ابتدا مطمئن شوید VM خاموش است و مقدار فعلی args فقط همان آرگومان موردنظر است. اگر args تنظیم دیگری هم دارد، حذف کامل آن ممکن است تنظیمات دیگری را نیز از بین ببرد؛ در آن حالت فقط آرگومان مربوط به کنترلر را با دقت اصلاح کنید.

اگر مقدار args دقیقاً همان خط نمونه است و تنظیم اضافی دیگری ندارد، می‌توان تنظیم سفارشی را با این دستور حذف کرد:

qm set 105 --delete args

این دستور کل گزینه args را از تنظیمات VM حذف می‌کند؛ بنابراین فقط وقتی استفاده کنید که مطمئن هستید مقدار دیگری در آن وجود ندارد. سپس تنظیمات را با qm config 105 بررسی کنید.

چک‌لیست نهایی

  • ☐ VMID درست انتخاب شده است.
  • ☐ از فایل تنظیمات نسخه پشتیبان گرفته شده است.
  • ☐ VM پیش از تغییر خاموش بوده است.
  • ☐ کنترلر PVSCSI و دیسک‌های موجود تغییر نکرده‌اند.
  • ☐ آرگومان VirtIO SCSI در پیکربندی ثبت شده است.
  • ☐ VM بدون خطا روشن شده است.
  • ☐ کنترلر در Device Manager بررسی شده و درایور مناسب نصب است.
  • ☐ اثر روش سفارشی بر Backup/Restore و Migration در محیط موردنظر آزمایش شده است.
یادآوری برای همکاران: ابتدا روی VM آزمایشی انجام دهید. VMID، مسیر ISO و نسخه Proxmox ممکن است در سرور شما متفاوت باشد. خروجی موفق یک محیط، تضمین‌کننده موفقیت روی همه محیط‌ها نیست.
